三、ViewController 生命周期（C++ 类比）

阶段OC 方法C++ 类比做什么

⚠ OC 坑：dealloc 里必须 removeObserver（KVO）和 removeObserver: name:（NSNotification），否则观察者引用已释放的对象 → crash。C++ 没有这个问题，因为没有自动通知机制。

四、5 种 View ↔ ViewModel ↔ Model 通信模式

① Block ② NSNotification ③ KVO ④ Delegate ⑤ Target-Action

① Completion Block（回调闭包）

一句话：View 把一个闭包传给 VM，VM 调完 Model 后在闭包里把结果传回 View。

View 端代码（RootViewController.m）

// 在 bindViewModel 里设置 block 回调
__weak typeof(self) weakSelf = self;
self.viewModel.blockResultHandler = ^(NSString *message) {
    [weakSelf showToast:message];   // 更新 UI
};

ViewModel 端代码（MainViewModel.m）

// Pattern 1: Completion Block
- (void)fetchViaBlock {
    __weak typeof(self) weakSelf = self;
    [self.model fetchDataWithTag:@"Block" completion:^(NSString *result, NSError *err) {
        dispatch_async(dispatch_get_main_queue(), ^{
            __strong typeof(weakSelf) self = weakSelf;
            if (!self) return;
            NSString *msg = err ? err.localizedDescription : result;
            self.blockResultHandler(msg);  // 调用 View 传来的 block
        });
    }];
}

✅ 优点

最简单直接，一个闭包搞定。代码都在一个文件里，容易追踪。

❌ 缺点

一对多能力弱。VM 只持有一个 block，多个 View 不能同时观察。block 里容易循环引用（必须用 __weak）。

C++ 类比：就是 std::function<void(const std::string&)> 回调。aria 里 Property<T>::on_changed(fn) 就是这个模式。

② NSNotification（通知中心）

一句话：VM 发一个全局通知，View 监听这个通知，收到后更新 UI。一对多广播。

View 端代码

// 在 bindViewModel 里注册监听
[[NSNotificationCenter defaultCenter]
    addObserver:self
       selector:@selector(onNotificationResult:)
           name:MVVMNotificationBlockResult
         object:nil];

// 回调方法
- (void)onNotificationResult:(NSNotification *)notification {
    NSString *result = notification.userInfo[MVVMNotificationResultKey];
    [self showToast:result];
}

// ⚠ dealloc 里必须移除！
- (void)dealloc {
    [[NSNotificationCenter defaultCenter] removeObserver:self];
}

ViewModel 端代码

- (void)fetchViaNotification {
    __weak typeof(self) weakSelf = self;
    [self.model fetchDataWithTag:@"Notification" completion:^(NSString *result, NSError *err) {
        dispatch_async(dispatch_get_main_queue(), ^{
            NSString *msg = err ? err.localizedDescription : result;
            // 发送全局通知（广播）
            [[NSNotificationCenter defaultCenter]
                postNotificationName:MVVMNotificationBlockResult
                              object:weakSelf
                            userInfo:@{MVVMNotificationResultKey: msg}];
        });
    }];
}

✅ 优点

一对多广播，多个 View 可同时监听同一个通知。松耦合，VM 不需要知道谁在听。

❌ 缺点

字符串 key 容易拼错（编译不检查）。类型不安全（userInfo 是 NSDictionary）。调试困难（不知道谁发的、谁收的）。

C++ 类比：类似 aria 的 EventBus::publish<T>(event)，或 Qt 的 emit signal()。全局发布/订阅模式。

③ KVO（Key-Value Observing）

一句话：View 观察 VM 的某个属性，VM 改属性时自动通知 View。天然响应式。

View 端代码

// 注册 KVO 观察
[self.viewModel addObserver:self
                 forKeyPath:@"kvoResult"
                    options:(NSKeyValueObservingOptionNew)
                    context:self.kvoContext];

// KVO 回调（系统自动调用）
- (void)observeValueForKeyPath:(NSString *)keyPath
                      ofObject:(id)object
                        change:(NSDictionary *)change
                       context:(void *)context {
    if (context != self.kvoContext) return;
    NSString *newVal = change[NSKeyValueChangeNewKey];
    [self showToast:newVal];
}

// ⚠ dealloc 里必须移除！
[self.viewModel removeObserver:self forKeyPath:@"kvoResult" context:ctx];

ViewModel 端代码

- (void)fetchViaKVO {
    self.kvoStatus = @"Loading...";
    __weak typeof(self) weakSelf = self;
    [self.model fetchDataWithTag:@"KVO" completion:^(NSString *result, NSError *err) {
        dispatch_async(dispatch_get_main_queue(), ^{
            NSString *msg = err ? err.localizedDescription : result;
            weakSelf.kvoStatus = @"Done";
            weakSelf.kvoResult = msg;  // 写属性 → 自动触发 KVO 通知
        });
    }];
}

✅ 优点

天然响应式，写属性就自动通知。不需要手动发通知或调 block。aria 的 Property 本质就是这个模式。

❌ 缺点

OC 的 KVO 键是字符串（@"kvoResult"），拼错不报错。必须手动 removeObserver。context 指针要小心。

C++ 类比：就是 aria 的 Property<T>::set(v) → 自动通知所有 observer。Swift 有 @Published 属性包装器，OC 用 KVO 实现同样效果。

④ Protocol Delegate（协议委托）

一句话：VM 定义一个协议（interface），View 实现这个协议，VM 调协议方法通知 View。Apple 推荐范式。

定义协议（MainViewModel.h）

@protocol MainViewModelDelegate <NSObject>
@optional
- (void)viewModel:(id)vm didReturnResult:(NSString *)result pattern:(NSString *)pattern;
- (void)viewModel:(id)vm didReturnError:(NSString *)error pattern:(NSString *)pattern;
@end

View 端代码

// 声明遵循协议
@interface RootViewController () <MainViewModelDelegate>
@end

// 设置 delegate
self.viewModel.delegate = self;

// 实现协议方法
- (void)viewModel:(id)vm didReturnResult:(NSString *)result pattern:(NSString *)pattern {
    [self showToast:[NSString stringWithFormat:@"[Delegate] %@", result]];
}

ViewModel 端代码

- (void)fetchViaDelegate {
    __weak typeof(self) weakSelf = self;
    [self.model fetchDataWithTag:@"Delegate" completion:^(NSString *result, NSError *err) {
        dispatch_async(dispatch_get_main_queue(), ^{
            if (err) {
                [weakSelf.delegate viewModel:weakSelf didReturnError:err.localizedDescription];
            } else {
                [weakSelf.delegate viewModel:weakSelf didReturnResult:result];
            }
        });
    }];
}

✅ 优点

类型安全，编译期检查。Apple 官方推荐范式。方法签名清晰，一目了然。

❌ 缺点

只能一对一（一个 delegate）。需要写 protocol 定义 + 实现，代码量多一些。

C++ 类比：就是纯虚基类（接口）。@protocol ≈ class IDelegate { virtual void onResult(...) = 0; }，View 实现这个接口。aria 的 IViewAdapter 就是这个模式。

⑤ Target-Action（目标-动作）

一句话：VM 持有 target（对象）+ selector（方法名），调 Model 回来后用 performSelector: 调 View 的方法。Apple NSControl 经典模式。

View 端代码

// 注册 target + selector
self.viewModel.targetActionTarget = self;
self.viewModel.targetActionSelector = @selector(targetActionCallback:);

// 回调方法
- (void)targetActionCallback:(NSString *)message {
    [self showToast:[NSString stringWithFormat:@"[Target-Action] %@", message]];
}

ViewModel 端代码

- (void)fetchViaTargetAction {
    __weak typeof(self) weakSelf = self;
    [self.model fetchDataWithTag:@"TargetAction" completion:^(NSString *result, NSError *err) {
        dispatch_async(dispatch_get_main_queue(), ^{
            NSString *msg = err ? err.localizedDescription : result;
#pragma clang diagnostic push
#pragma clang diagnostic ignored "-Warc-performSelector-leaks"
            [weakSelf.targetActionTarget performSelector:weakSelf.targetActionSelector
                                                  withObject:msg];
#pragma clang diagnostic pop
        });
    }];
}

✅ 优点

Apple NSControl 经典模式（UIButton 就是这样工作的）。与 UI 控件天然契合。

❌ 缺点

performSelector: 是运行时字符串匹配，编译不检查。ARC 下需要 #pragma 抑制警告。

C++ 类比：类似函数指针 void (*callback)(const char*)，但更灵活（运行时动态绑定）。aria 的 Command<> 就是这个模式。

五、5 种模式对比表

模式 View→VM VM→View 一对多 类型安全 代码量 推荐场景
① Block 设 block 属性 调 block ❌ 弱 ✅ 最少 简单回调，快速原型
② Notification 调方法 post 通知 ✅ 强 ❌ 中等 全局广播，跨模块通信
③ KVO 调方法 写属性 ✅ ❌ 字符串 中等 属性绑定，响应式 UI
④ Delegate 调方法 调 delegate ❌ 一对一 ✅✅ 最强 最多 Apple 推荐，正式项目
⑤ Target-Action 调方法 performSelector ❌ ❌ 运行时 少 UI 控件事件，经典 Cocoa

六、C++ vs OC 速查表

C++ 概念OC 等价说明
class Foo {};@interface Foo : NSObject @end类定义。OC 所有类继承 NSObject
Foo* p = new Foo();Foo *p = [[Foo alloc] init];创建对象。OC 用消息发送语法 [obj method]
delete p;ARC 自动释放OC 有 ARC（自动引用计数），不需要手动 delete
std::function<void()>void (^block)(void)Block 就是 OC 的闭包/lambda
virtual void f() = 0;@protocol / @optional纯虚函数 ≈ OC 协议
signal-slot (Qt)NSNotificationCenter全局发布/订阅
property + observerKVO (addObserver:)属性变化自动通知
std::shared_ptrstrong property强引用，ARC 管理
std::weak_ptrweak property弱引用，不延长生命周期
RAIIdealloc资源释放。OC 在 dealloc 里清理
#include#importOC 的 import 自动去重
namespace无直接等价OC 用类前缀（如 HY、YB）代替
template<T>无直接等价OC 没有泛型，用 id（类似 void*）
std::threaddispatch_async(queue, ^{})GCD（Grand Central Dispatch）线程池
co_await无直接等价OC 没有协程，用 block + GCD 模拟
⚠ OC 最容易踩的 3 个坑（C++ 开发者必读）：
  1. NSWindow.isReleasedWhenClosed = YES：关闭窗口时自动释放，有强引用也无效。必须设 = NO
  2. KVO 必须 removeObserver：不移除就 crash。C++ 没有这个问题
  3. Block 循环引用：block 捕获 self → self 持有 block → 循环。必须用 __weak

七、Model 层代码（所有模式共用）

// DataModel.h
@interface DataModel : NSObject
- (void)fetchDataWithTag:(NSString *)tag completion:(void (^)(NSString *, NSError *))completion;
@end

// DataModel.m — 模拟 2s 网络延迟
- (void)fetchDataWithTag:(NSString *)tag completion:(Completion)completion {
    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
        [NSThread sleepForTimeInterval:2.0];     // 模拟延迟
        BOOL success = arc4random_uniform(100) > 5; // 95% 成功率
        if (success) {
            completion([NSString stringWithFormat:@"[%@] ✅ OK", tag], nil);
        } else {
            completion(nil, [NSError errorWithDomain:...]);
        }
    });
}

九、aria 统一模式（替代以上 5 种）

🎉 核心思想：用 aria 的 Property<T> + Command<Args...> 统一替代上面 5 种 OC 通信模式。ViewModel 和 Model 全部用 C++ 写，View 层用 .mm（ObjC++）桥接。

改造前后对比

原来（OC 5 种模式）现在（aria 统一）说明
blockResultHandler block 回调Property<string>::on_changed(fn)信号订阅 ≈ block
NSNotificationCenter 广播同上（多处 on_changed）一个 Property 可多个订阅者
KVO addObserver:forKeyPath:Property::set(v) 自动通知KVO 最佳替代，零字符串
@protocol MainViewModelDelegate不需要，on_changed 直接订阅去掉了 protocol 定义
target + selector + performSelector:Command<string>::execute(tag)类型安全的命令模式

新的 MainViewModel.hpp（C++ 重写）

class MainViewModel : public aria::binding::ViewModel {
public:
    // 可观察属性 —— 替代 KVO / block / notification / delegate
    aria::Property<std::string> result_text{""};
    aria::Property<std::string> status_text{"Tap a button"};
    aria::Property<bool>        is_loading{false};

    // 命令 —— 替代 target-action
    aria::Command<std::string> fetch_cmd;

    MainViewModel(std::shared_ptr<DataModel> model)
        : model_(std::move(model)),
          fetch_cmd([this](const std::string& tag) { doFetch(tag); })
    {}
};

View 层绑定（RootViewController.mm）

// 绑定属性变化 → 更新 UI（替代所有 5 种模式的回调）
_vm->track(_vm->status_text.on_changed([](const std::string& val) {
    dispatch_async(dispatch_get_main_queue(), ^{
        statusLabel.stringValue = [NSString stringWithUTF8String:val.c_str()];
    });
}));

// 绑定按钮 → 命令（替代 target-action）
btn.target = wrapper;   // AppKitClickWrapper 桥接 ObjC → C++
btn.action = @selector(fire);
wrapper.callback = [vm, tag]() { vm->fetch_cmd.execute(tag); };

// 原来 5 种模式的 fetch 方法 → 现在全是一个
_vm->fetch_cmd.execute("Block");  // 所有按钮统一走这一个入口

✅ aria 统一后的好处

1. 5 种模式 → 1 种
2. ViewModel/Model 纯 C++，跨平台复用
3. 类型安全，零字符串 key
4. 自动追踪订阅，RAII 释放，不需要 removeObserver
5. Command 自带 can_execute 断言

⚠ 注意事项

1. .mm 文件中 lambda 不能直接捕获 self，需用 __weak/__strong 或先 capture shared_ptr
2. typeof(self) 在 lambda 里可能报错，用显式类型 RootViewController *
3. CMake 的 clang 比 Xcode 更严格（lambda 捕获检查）
